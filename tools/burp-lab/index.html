Intercepta.
Modifica.
Entiende.

Un pequeño sitio con fallos intencionados. Envía una petición, mira lo que viaja y descubre qué pasa cuando cambias las reglas.

Tu primera peticiónhttp://127.0.0.1:8090
  1. Abre Burp → Temporary project → Use Burp defaults → Start Burp.
  2. En Proxy → Intercept → Open browser, abre esta URL.
  3. Activa Intercept on y prueba un formulario. Pulsa Forward para continuar.
  4. En HTTP history, botón derecho → Send to Repeater. Cambia un valor y pulsa Send.

Si la página se queda esperando, revisa las peticiones retenidas en Intercept.

09 ejercicios disponibles
01 / buscadorXSS reflejado

Lo que escribes vuelve.

El servidor devuelve tu búsqueda dentro del HTML sin escaparla. Observa cómo interpreta el navegador la respuesta.

Ver práctica con Repeater

Prueba <img src=x onerror=alert('demo')>. Repeater muestra la respuesta; abre la URL en el navegador de Burp para ver la ejecución.

02 / catálogoSQL injection

Detrás del catálogo.

Una consulta real a SQLite concatena tu búsqueda. Hay un producto oculto que no debería aparecer.

Ver práctica con Intruder

Captura GET /products?q=Teclado. Prueba una comilla y después ' OR 1=1 -- . Compara estados, longitudes y productos. Intruder Community tiene velocidad limitada.

03 / identidadEnumeración

Una pista de más.

El login responde distinto cuando falla el usuario o la contraseña. Credenciales ficticias: demo / burp123.

Ver práctica con Intruder

Envía a Intruder y marca solo username. Prueba ana, demo y admin. Compara el cuerpo. La cookie de sesión también aparece en HTTP history.

04 / perfilesIDOR

¿De quién es esto?

El identificador decide qué perfil devuelve la API. El servidor no comprueba si te pertenece.

Ver práctica con Comparer

Cambia id=1 por id=2 en Repeater. Envía ambas respuestas a Comparer para comparar los datos expuestos sin autorización.

05 / cestaPrecio manipulable

Tú pones el precio.

Una tienda ficticia confía en el precio enviado por el cliente para calcular el importe del pedido.

Ver práctica con Proxy

Intercepta el POST y cambia price=89 por price=0.01. Pulsa Forward y observa el total. También acepta JSON desde Repeater.

06 / tablónXSS almacenado

Un mensaje persistente.

Los comentarios se guardan en memoria y se muestran como HTML. Reiniciar datos vacía el tablón.

Ver práctica de almacenamiento

Publica <b>Mensaje de prueba</b> y luego el ejemplo de XSS del ejercicio 01. Vuelve a /comments para comprobar que persiste.

07 / navegaciónOpen redirect

Un destino libre.

La siguiente página depende de un parámetro. Examina la cabecera Location y el código 302.

Ver práctica con Repeater

Prueba https://example.com como destino. El servidor acepta un dominio externo sin validarlo. Repeater permite inspeccionar el 302 antes de seguirlo.

08 / cuentaSin token CSRF

Cambia sin preguntar.

Tras iniciar sesión, cambia el correo de Ana. No se comprueba un token CSRF ni la cabecera Origin.

Ver práctica de sesión

Inicia sesión en 03. En Repeater elimina o cambia Origin: el POST sigue aceptándose. La cookie SameSite=Lax limita ataques entre sitios; la ausencia de token por sí sola no demuestra un ataque CSRF desde cualquier origen.

09 / archivosTraversal virtual

Fuera de la carpeta.

Un sistema de archivos simulado ilustra los recorridos de ruta. Nunca accede a archivos reales del ordenador.

Ver práctica con Decoder

Prueba ../private/demo.txt y su versión URL encoded con Decoder. Se devuelve un secreto ficticio. Este ejercicio es una simulación, no una lectura arbitraria del disco.
